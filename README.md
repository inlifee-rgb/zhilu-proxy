# 智路 · 智能分流代理（Chrome 扩展）

> 中国域名 / IP 直连，海外流量全部走代理。代理决策写在 Chrome 自己的 PAC 里，**不依赖任何系统代理开关**——即使 Clash / 代理客户端的「系统代理」是关闭的，装了本扩展的这个 Chrome 依然按规则分流。

## 适用场景

如果你在国内用 Chrome，又开了本地代理客户端（Clash / Mihomo / v2rayN / sing-box 等），这个扩展解决一个很具体的问题：**让国内网站直连、国外网站走代理，且不用开代理客户端的「系统代理」开关**。

典型情况：

- **不想全局翻**：只希望 Chrome 智能分流——百度、淘宝、政府网站直连不走代理，Google、GitHub、海外服务走代理。
- **系统代理开关不便开**：公司/公用电脑没权限改系统代理，或者你不想让微信、游戏等其他软件也走代理——本扩展只管这一个 Chrome。
- **代理客户端端口乱**：装了 Clash 但 mixed-port 不是默认的 7890，扩展打开面板自动扫描端口并填入，不用手动找。
- **怕配错断网 / 怕配了没生效**：代理挂了自动临时直连（fail-open）；面板并排显示「代理出口 IP」和「本机真实 IP」，一眼看出到底有没有走代理。

一句话：**装上、允许代理权限、确认显示「PAC 智能分流」，之后开不关系统代理都由它自己分流。**

## 它能做什么

- **智能分流**：中国域名、中国 IP 段直连；其余全部走你指定的 HTTP 代理（默认 `127.0.0.1:7897`）。
- **与实际系统代理解耦**：用 `chrome.proxy` API 注入 PAC，由 Chrome 自己决策，不用开 Clash 的「系统代理」或 TUN。
- **网络出口实时探测**：面板并排显示「代理出口 IP / 地区」和「本机真实公网 IP / 地区」，并自动判定代理是否真的生效。探测请求本身经过 PAC（`cloudflare.com/cdn-cgi/trace` 走代理、`myip.ipip.net` 走直连），所以显示的是**实际分流效果**，不是理论值。
- **本地代理内核检测**：打开面板即扫描 12 个常见代理端口，识别 Clash Verge / Mihomo / v2rayN / sing-box 等内核并自动填入端口；没装内核时明确提示并给出官网安装入口，避免「配了代理却没内核」的假象。
- **fail-open**：代理端口不通时自动临时直连，不会断网；恢复后自动切回。
- **自定义规则**：域名级强制直连 / 强制代理，支持后缀匹配。
- **规则库自动更新**：每天自动从 APNIC 拉取最新中国 IP 段并重建 PAC，避免内置基线过期误判；拉取失败静默保留旧规则，始终有离线基线兜底。面板「规则覆盖」处显示更新于几天前（超 30 天标黄），诊断详情里可手动「更新规则库」；当前页面命中依据（如「中国域名库 / 中国 IP 网段 / 海外域名」）也在健康卡里直接显示。
- **浅色磨砂玻璃 UI + 五种交互动效**：半透明模糊卡片叠在缓缓流动的蓝紫青极光光晕上（玻璃需要底层动态色彩才透得出层次），浅色主题。
  - **液态玻璃选中**：分流模式切换时，半透明胶囊用五段关键帧模拟水滴——起步压缩、途中沿运动方向拉伸并垂直收窄（体积守恒）、过冲后回弹定格，边缘带细高光。
  - **聚光卡片**：健康卡 / 内核卡 / 出口卡跟随光标显示径向光斑、局部提亮边框，并做不超过 4° 的 3D 倾斜，移出平滑复原。
  - **边缘流光**：健康卡边框有一道柔和渐变光束持续绕行。
  - **点击展开放大**：健康卡「详情」按钮把卡片原位放大为诊断视图（实际模式 / 控制权 / 端口 / 内核 / 覆盖率），关闭原路收回。
  - **玻璃停靠栏**：底部浮动 dock，悬停时当前图标放大、相邻联动、上方显示名称；点击滚动定位。
  - **当前页面路由（合并进健康卡）**：健康卡里的「中国域名 / IP 直连 ↔ 海外域名 / IP 走代理」示意条会随当前标签实时点亮——当前页面走哪条路，那一侧就亮起（带脉冲小灯）并显示域名（如 `当前 baidu.com`），另一侧灰掉；logo 猫头右上角同步一个极小状态灯：**直连=绿、走代理=紫、无法判定=灰/琥珀**。用与 PAC 完全相同的规则判定（如 `baidu.com → 直连 · 中国域名库`、`google.com → 走代理 · 海外域名`），切换分流模式后自动重判。需 `tabs` 权限读取当前标签地址。
  - **工具栏图标随路由变色**：浏览器工具栏里的扩展图标本身就是「猫头 + 右下角状态点」——**直连=绿点 / 走代理=紫点 / 暂停=灰点 / 写入失败=红点**，切换标签或页面导航后实时更新。色点带深色描边 + 白圈，16px 下也清晰可辨（早期用 badge 文字 `CN` / `●` 会显示成难看的黑点套绿框，已弃用）。
  - **流量统计**：独立的流量卡按「直连 / 代理」分路显示本次会话累计的请求数与传输字节（上传取请求体长度、下载取响应 `Content-Length`），用 `webRequest` 观察模式按 PAC 同源规则归类，排除扩展自身探测流量；本地累计，不上传。位于「网络出口」卡之后。
  - **智路猫**：在健康卡 / 内核卡 / 出口卡 / 流量卡之间**随机斜跳巡游**（蓄力 → 抛物线上抛 → 斜向落地），趴在卡片上边线，慢摇尾巴、眨眼、呼吸；会避开底部 dock 遮挡区，滚动或卡片显隐时自动重算位置。状态互斥、不打架，尊重系统「减少动态效果」设置。

> **出口探测 ≠ 当前页面路由**：「网络出口」卡里的代理出口 IP 来自一次海外探测请求（Cloudflare），它只能说明**代理通道通不通**，不代表你正在看的页面走了代理。当前页面走哪条路，一律看健康卡里点亮的那半边示意条 + logo 灯。

## 分流判据（PAC，优先级从上到下）

1. 本地 / 内网地址 → `DIRECT`
2. 自定义「强制直连」域名 → `DIRECT`
3. 自定义「强制代理」域名 → `PROXY`
4. `.cn` 后缀 + 122 个内置中国域名后缀 → `DIRECT`
5. `dnsResolve()` 解析 IP，命中中国网段 → `DIRECT`
6. 其余全部 → `PROXY <host>:<port>`

规则数据来自 APNIC `delegated-apnic-latest`：**5,500 条 IPv4 CIDR + 2,019 条 IPv6 CIDR + 122 个域名后缀**，压缩后 `data-cn.js` 约 115KB。

## 安装

1. 克隆本仓库到本地
2. 打开 `chrome://extensions`，开启右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择仓库根目录（含 `manifest.json` 的那一层）
4. 安装弹窗会要求「**更改代理设置**」权限 → 点**允许**（不给这个权限无法接管代理）
5. 点工具栏图标，确认「Chrome 实际模式」显示 **PAC 智能分流**

> 首次加载若出口探测报权限错误，移除扩展后重新「加载已解压的扩展程序」一次即可。

## 配置

默认端口 `7897`（常见 Clash Verge mixed-port 之一，非通用默认 7890）。若你的代理端口不同，在面板「代理入口」直接改 host + port。

面板功能：

## 工作原理

```
网页请求 → Chrome 网络栈 → 本扩展注入的 PAC（FindProxyForURL）
                              ├─ 命中中国域名/IP → DIRECT
                              └─ 其余 → PROXY 127.0.0.1:<port>
                                          → 你的本地代理客户端 → 海外出口
```

探测「代理出口」时，请求 `https://www.cloudflare.com/cdn-cgi/trace` 被 PAC 判为海外 → 走代理 → 得到出口 IP / 国家 / 机场代码（不限流、无需 key）；
探测「本机真实」时，请求 `https://myip.ipip.net` 被 PAC 判为国内 → 直连 → 得到本机公网 IP。

## 隐私

- 不上传任何浏览数据；规则数据在本地生成。
- 出口探测只请求两个公开的 IP 信息接口（`www.cloudflare.com/cdn-cgi/trace` / `myip.ipip.net`），用于显示当前出口；可随时关闭面板不发请求。
- Clash API 相关的 secret 只存在扩展本地存储，不写入代码、不上传。

## 边界（说清楚，免得误会）

- 只接管**装了本扩展的这个 Chrome**；其他浏览器、客户端软件、系统流量不受影响。要全系统分流请用系统代理或 TUN。
- DNS 判定依赖系统解析。若被污染把海外域名解析成中国 IP，会误判直连——此时关掉「DNS 解析判定」，只用域名库 + 自定义规则即可。
- 出口探测用 Cloudflare trace，不限流、无需 API key；早期版本用的 ipinfo.io 因共享出口常被限流（HTTP 429）已弃用。

## 数据更新

从 [APNIC](https://ftp.apnic.net/apnic/stats/apnic/delegated-apnic-latest) 下载 `delegated-apnic-latest`，取 `apnic|CN|` 行存为 `tools/apnic-cn-lines.txt`，运行 `python tools/build_cn_data.py tools/apnic-cn-lines.txt` 重新生成 `data-cn.js`。中国域名后缀在 `tools/cn-domains.txt` 维护。

`data-cn.js` 只是**离线基线**。扩展运行时还会每天（service worker 的 `zhilu-rules` alarm）直接从 APNIC 拉最新数据存入 `chrome.storage.local`，加载时用存储版覆盖内置基线（`background.js` 的 `parseApnic` / `applyStoredRules` / `updateRulesFromApnic`）。拉取失败或数据不完整（v4<3000 / v6<300）一律不覆盖旧规则。域名库是人工维护的，始终用内置版本。要立即更新可打开面板 → 诊断详情 → 「更新规则库（APNIC）」。
